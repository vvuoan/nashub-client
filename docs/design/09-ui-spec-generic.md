# 09 通用电视端 UI 设计规范（10-foot UI）

> 适用范围：任何 16:9 大屏（电视、投影、车机后排屏）应用。与具体产品无关，不含任何项目页面结构。
> 基准画布：1920×1080。所有数值以「设计像素（dp@1080p）」表述，落地时按 §1 缩放。
> 依据标签：
> - **[规范]** 平台规范原则（Apple tvOS HIG、Android TV / Google TV 设计指南）
> - **[惯例]** 行业通行做法（流媒体 TV 端、机顶盒 UI）
> - **[推导]** 由观看距离、视角、像素密度计算的数值
> - **[实测]** 可由对比度/几何公式直接验证
> - **[经验]** 工程经验值，需在目标机型上验证（不作为硬标准）
>

## 0. 符号与基本假设

| 符号 | 含义 | 默认 |
| --- | --- | --- |
| `W0 × H0` | 设计基准 | 1920×1080 |
| `W × H` | 实际视口（CSS px） | 随设备 |
| `s` | 缩放因子 | `min(W/1920, H/1080)` |
| `M` | 页面左右边距（视觉边距） | 80（常用 48–120，阅读页可到 160） |
| `G` | 列间距 | 40（区间 16–48） |
| `N` | 列数 | 4/5/6/7 |
| `C` | 内容区宽度 | `W0 − 2M` |
| `cw` | 列宽 / 卡片宽 | `(C − (N−1)G) / N` |
| `r` | 圆角 | 见 §4.4 |

假设：16:9、横屏、观看距离 2.5–4 m、单焦点（遥控器方向键 + OK/返回）、无鼠标、无触摸（若支持触摸见 §8 备注）。

## 1. 基准与缩放

### 1.1 缩放因子

```
s = min(W / 1920, H / 1080)          // 推荐：letterbox 友好，不裁切
s = W / 1920                          // 仅在严格 16:9 且不做安全区补偿时使用
```

任何设计尺寸 `d` 落地为 CSS 尺寸：`d × s`。

### 1.2 标准分辨率换算表

| 视口 | s | 80 边距 → | 260 卡片 → | 24 字号 → |
| --- | --- | --- | --- | --- |
| 1280×720 | 0.667 | 53.3 | 173.3 | 16.0 |
| 1920×1080 | 1.000 | 80 | 260 | 24 |
| 2560×1440 | 1.333 | 106.7 | 346.7 | 32.0 |
| 3840×2160 | 2.000 | 160 | 520 | 48 |
| 7680×4320 | 4.000 | 320 | 1040 | 96 |

> 「2K」在电视语境里通常就是 1920×1080；2560×1440 是显示器规格，接入电视时按 `s=1.333` 处理即可。[惯例]

### 1.3 什么时候不能等比放大

| 项目 | 处理方式 | 原因 |
| --- | --- | --- |
| 字体 | 按档位取整（见 §7.4），不要 `24 × 1.333 = 32.0` 以外的任意小数 | 亚像素字形发虚 |
| 1px 发丝线 | 用物理 1px 或 `max(1px, 1×s)`，不要 `0.67px` | 某些 GPU 上 0.67px 直接消失 [经验] |
| 焦点环宽度 | 1080p 最少 3px，4K 最少 6px；按 `max(3, round(3×s))` | 3m 外可见性下限 [推导] |
| 模糊半径 | `blur × s` 后再 clamp 到 0–96；超过 96 在低端盒子掉帧 | 性能上限 [经验] |
| 位图资源 | 按 §5 的 `设备像素` 重新取图，不放大 1080p 图 | 放大即糊 |
| 最小点击/焦点目标 | 1080p ≥ 48×48，4K ≥ 96×96（物理） | 遥控器粗定位 [规范] |
| 阴影 | 位移与模糊按 `s` 放大，透明度不变 | 保持视觉重量一致 |

### 1.4 取整规则

- 位置/尺寸：保留 0.5 的倍数（`round(x×2)/2`）。
- 字号：整数；同一层级的所有字号各自取整，不做相对缩放链。
- 圆角：整数；`< 4` 一律取 4，避免「看不出圆角」。
- 间距：落在 §6 的阶梯上；不为凑整牺牲列宽，先调 `G`。

## 2. 安全区

### 2.1 三个概念

| 概念 | 定义 | 1080p 数值 |
| --- | --- | --- |
| 过扫描区（overscan） | 老电视可能裁掉的边缘 | 四周 5% ≈ 96×54（部分设备 3.5% ≈ 67×38）[规范] |
| 动作安全区（action safe） | 关键动作/焦点必须落在其内 | 93% ≈ 左右 67、上下 38 [惯例] |
| 标题安全区（title safe） | 文字必须落在其内 | 90% ≈ 左右 96、上下 54 [惯例] |
| 视觉边距（visual margin） | 设计上的留白，不等于安全区 | 推荐 80（常用 48–120，阅读页可到 160） |

### 2.2 推荐值

| 场景 | 左右 | 上下 | 说明 |
| --- | --- | --- | --- |
| 紧凑型（信息密度高） | 64 | 48 | 对应 §3.3 紧凑预设；绝对下限 48 / 40，不得再低 |
| **默认** | **80** | **60** | 与 6 列 260 卡片自洽（见 §3.4） |
| 影院感（大图为主） | 96–120 | 64–80 | 首页、详情主视觉；120 对应 §3.3 影院预设 |
| 设置/表单 | 120–160 | 64 | 阅读型页面可更宽 |

规则：

1. 所有可交互元素的**焦点环外缘**必须落在动作安全区内。
2. 所有文字必须落在标题安全区内；主标题可贴视觉边距，但不得进入 overscan。
3. 背景图/氛围层可以铺满，但不得承载信息。
4. 同一产品内只允许一套 `M`；不同页面用「内容区宽度」区分，不要改边距。

## 3. 网格

### 3.1 列数选择

| 列数 | 单卡宽（默认 M=80/G=40） | 适用 | 不适用 |
| --- | --- | --- | --- |
| 4 | 410 | 大图推荐位、详情相关推荐、儿童模式 | 片库浏览（效率低） |
| 5 | 320 | 首页货架、混合内容、卡片带文字 | 超大库 |
| 6 | 260 | **海报墙默认**、影视库、收藏 | 小屏（< 1280） |
| 7 | 217 | 高密度库、搜索结果、管理员视图 | 客厅 3m 观看（字太小） |
| 8 | 185 | 仅列表式信息（非图片卡） | 任何需要读文字的场景 |

> 依据：3 m 观看距离下，6 列 2:3 海报的可读卡名下限约 20px；7 列时卡宽 217、卡名只能取 Label 下限 20px，已无余量。[推导]

### 3.2 列宽公式

```
C  = W0 − 2M
cw = (C − (N−1) × G) / N
```

### 3.3 标准网格表（1920×1080）

**A. 默认：M=80，G=40**

| --- | --- | --- | --- | --- |

| 5 | 320 | 480 | 180.0 | 320 |
| 6 | **260** | **390** | **146.25** | 260 |

| 7 | 235.4 | 353.1 | 132.4 |

**C. 影院：M=120，G=48**（内容区 1680）

| N | cw | 2:3 高 | 16:9 高 |

### 3.4 取整与「末列悬空」

优先让 `cw` 为整数：先固定 `M` 与 `N`，反解 `G`：

```
G = (C − N × cw) / (N − 1)
```

例：`C=1760, N=6, cw=260` → `G=(1760−1560)/5=40`。这就是「6 列 260 + 40 间距」的由来。[推导]

若 `G` 反解出小数（如 40.5），两种合法做法：

1. 把 `G` 取整，允许 `cw` 带 0.5（`260.4`），布局用 flex 自动分配，不做绝对定位；
2. 保持 `cw` 整数，把余数平均加到左右边距（`M` 变大 2–4），**不要**让最后一列单独变宽。

## 4. 卡片规格

### 4.1 比例与用途

| 比例 | 用途 | 说明 |
| --- | --- | --- |
| 2:3 海报 | 影视条目、收藏、搜索结果 | 信息密度最高，默认 |
| 16:9 横版 | 继续观看、剧集、直播、推荐位 | 与视频画幅一致 |
| 1:1 方卡 | 人物、音乐、播客、频道 | 头像/封面友好 |
| 5.4:1 横幅 | 运营位、活动、单条强推荐 | 宽幅主视觉，**只能跨列/通栏**，不得按单列取宽（§4.6） |
| 2:1 主视觉 | 详情页头图、影院 hero | 可同时容纳片名、简介与按钮组（§4.6） |

> 1:1.5 竖幅与 2:3 是同一比例（宽:高 = 1:1.5 = 2:3），已作为海报收录；其余常见比例未收录的原因见 §4.8。

### 4.4 圆角与宽度的关系

```
r = clamp(6, 0.055 × w, 28)      // 常规卡片
r = clamp(12, 0.08 × w, 36)      // 大图/主视觉
r = clamp(8, 0.10 × h, 36)       // 宽幅横幅（5.4:1），按短边算
```

| 卡宽 | 常规 r | 大图 r |
| --- | --- | --- |
| 200 | 11 | 16 |
| 260 | 14.3 → 14 | 20.8 → 21 |
| 320 | 17.6 → 18 | 25.6 → 26 |
| 410 | 22.6 → 23 | 32.8 → 33 |
| 640+ | 28（封顶） | 36（封顶） |

**横幅为什么不能沿用宽度公式**：5.4:1 通栏（1760×326）按 `0.055w` 会得到 97，被 28 截断；28 只占高度 8.6%，在 3 m 外几乎看不出圆角，观感接近直角。曲率是相对**短边**被感知的，所以横幅改为按高度计算：

| 横幅高 | 横幅 r | 对应宽度（5.4:1） |
| --- | --- | --- |
| 120 | 12 | 648 |
| 151 | 15 | 816 |
| 159 | 16 | 860 |
| 215 | 22 | 1160 |
| 280 | 28 | 1512 |
| 311–332 | 31–33 | 1680–1792 |

规则：横幅圆角不低于 8、不高于 36（36 以上开始「药丸化」，与卡片语言冲突）；半幅横幅与 2:3 卡同排时，圆角取两者较小值 +0～2，避免两种曲率并排。

规则：**常规卡**超过 8% 卡宽会显得「药丸化」（大图允许 8%，宽幅横幅按短边 10%）；低于 4% 在 3 m 外几乎不可见。[惯例]

**满幅与半幅的取法**

| 用法 | 宽度取法 | 数值（A / B / C） | 何时用 |
| --- | --- | --- | --- |
| 满幅（通栏） | `C = W0 − 2M` | 1760 / 1792 / 1680 | 页面第一区块、独立运营页、专题头图 |
| 半幅（网格对齐） | `span(k)`，一半宽度 | A 860、B 884、C 816 | **推荐**，与同排卡片共享列宽，切换布局不跳变 |
| 半幅（视觉对分） | `(C − G) / 2` | A 860、B 884、C 816 | 仅当横幅独占一行、旁边放的是文字或按钮组时 |

> 注意：半幅 860 与 3 张 2:3 卡（3×260+2×40 = 860）恰好相等，可与卡对齐；但 2 张卡只有 560，**不要**把 560 宽的横幅硬拉成 860。要并排就先算跨度。

#### 4.6.3 高度下限与替代比例

| 内容 | 最小高度 | 说明 |
| --- | --- | --- |
| 只有一行标题 | 120 | 32px 标题 + 上下 20 内边距 + 字底余量 |
| 标题 + 一行元信息 | 150 | 两行文字 + 内边距 |
| 标题 + 副标题 + 按钮 | 180 | CTA 高 56–64 |
| 通栏 hero | 280 | 有主视觉与文字压图 |

高度不足时的处理顺序：

1. **先加跨度**：能跨 3 列就不要跨 2 列（`h` 随宽度线性增长）。
2. **仍不足 120**：改用 16:9（`h = 0.5625w`，640 → 360），不要缩字号硬塞。
3. **需要两行文字 + 按钮，宽度只能到 860**：改用 2:1（860×430），文字压在图上更从容。
4. **宽度 ≥ 900 但高度预算被压缩**：把文字移出横幅，放在下方的卡下文字区，横幅只承载图片。

#### 4.6.4 横幅内的叠加安全区

| 项目 | 值 | 依据 |
| --- | --- | --- |
| 左右内边距 | `clamp(32, 0.05w, 80)` | 与 §2 标题安全区叠加后仍 ≥ 96 |
| 上下内边距 | `clamp(16, 0.12h, 48)` | 避免文字贴圆角与裁切边 |
| 文字块最大宽度 | 0.55w（通栏建议 0.5w） | 不压住主体/人物面部 |
| CTA 距左 | ≥ 48（通栏 64） | 与文字块左缘对齐 |
| CTA 距底 | ≥ 24 | 避免被进度条/角标干扰 |
| CTA 尺寸 | 高 56–64，圆角 8–12 | 遥控器焦点目标 ≥ 48 |
| 右侧预留 | ≥ 96 | 角标、评分、操作入口 |
| scrim | 横向 0→55%→85%，或纵向 0→45%→80% | 文字对比度 ≥ 7:1 |
| 文字对比 | ≥ 7:1 | §10.2 |

叠加规则：文字**永远**放在 scrim 覆盖区；只有纯图片的横幅才允许信息贴边。文字块与横幅圆角之间至少留 16，避免视觉上「被切角」。

| 16:9（1.78:1） | 0.562W | 0.185W | 67% | 中间 33% | ✕ 默认不裁 |

规则：

- 纵向裁掉 **≤ 60%** 视为安全；60–65% 必须确认主体在保留带内；**> 65% 不裁**。
- 16:9 剧照裁进 5.4:1 默认不允许：头像、字幕、构图重心极易被切。改用专用横幅图，或 `contain` + 两侧模糊/纯色填充，或退回 16:9 卡。
- 源图比 5.4:1 更窄（4:3、1:1、竖图）时，横向裁切会超过 70%，禁止用于横幅。
- 需要焦点裁切时用 `object-position` 指定，并保证保留带内主体完整。

### 4.7 横幅 / 横卡 / 主视觉的分工判据

| 判据 | 5.4:1 横幅 | 16:9 横卡 | 2:1 主视觉 |
| --- | --- | --- | --- |
| 内容条数 | 1 条 | ≥ 2 条（集合） | 1 条 |
| 最小宽度 | 648 | 任意 | 800 |
| 高度预算 | 120–332 | 110–270 | 300–880 |
| 文字承载 | 片名 + 1 行副标 + CTA | 卡下 1–2 行 | 片名 + 2–3 行简介 + 按钮组 |
| 是否网格成员 | 否，独占一行 | 是 | 否 |
| 典型位置 | 顶部运营位、活动、专题头图 | 继续观看、剧集、直播 | 详情页头图、影院 hero |
| 焦点 | 描边（禁止放大） | 放大 1.06 | 描边或 1.03 |

判据按顺序判断，命中即停：

1. 宽度 < 648 → **16:9**。
2. 需要 ≥ 2 行文字 + 按钮，且高度可到 300 → **2:1**。
3. 单条内容、独占一行、宽度 ≥ 900、高度 ≤ 332 → **5.4:1**。
4. 多条内容、需要网格/货架 → **16:9**。
5. 其余 → **16:9**（默认）。

### 4.8 未收录的常见比例及原因

| 比例 | 处理 | 原因 |
| --- | --- | --- |
| 1:1.5 竖幅 | 已收录 | 就是 2:3（宽:高 = 1:1.5），见 §4.2 |
| 3:2（横版剧照） | 不单列 | 与 2:3 互为横竖；容器用 16:9，源图 cover 裁切即可 |
| 3:4 竖卡 | 不单列 | 人物/竖版物料用 1:1 或 2:3 的 cover 裁切，尺寸档不再增加 |
| 4:3 | 不单列 | 仅老片/资料库；用 16:9 容器 + `contain` + 模糊底，不做独立容器 |
| 2.39:1 / 21:9 | 不单列 | 影片原生画幅，属于**源图**比例而非容器；容器仍用 16:9 或 5.4:1 |
| 1.85:1 | 不单列 | 与 16:9 差异 < 4%，肉眼难辨，不值得新增一档 |
| 9:16 竖屏 | 禁止 | 与 10-foot 横屏交互冲突，不提供入口 |

原则：**容器比例只保留能被网格整除、且能承载文字的那几档**；其余比例在资源侧用裁切/填充适配，避免尺寸表膨胀。

## 5. 图片资源

### 5.1 所需位图宽度

```
imgW ≥ cw × s × DPR × 1.15        // 1.15 是裁切/安全余量
```

- `s`：视口缩放（4K = 2）
- `DPR`：设备像素比（WebView 常见 1、1.5、2；部分 4K 盒子报 1 但物理是 2，用 `devicePixelRatio` 实测）
- 向上取到常见档位：240 / 320 / 480 / 640 / 800 / 960 / 1280 / 1600 / 1920 / 2560 / 3840 / 4096

### 5.2 标准档位表（2:3 海报）

| 卡片宽（1080p） | 1080p@1x | 1080p@2x | 4K@1x | 4K@2x |
| --- | --- | --- | --- | --- |
| 160 | 184 → 240 | 368 → 480 | 368 → 480 | 736 → 800 |
| 200 | 230 → 240 | 460 → 480 | 460 → 480 | 920 → 960 |
| 260 | 299 → 320 | 598 → 640 | 598 → 640 | 1196 → 1280 |
| 320 | 368 → 480 | 736 → 800 | 736 → 800 | 1472 → 1600 |
| 410 | 472 → 480 | 943 → 960 | 943 → 960 | 1886 → 1920 |

### 5.3 横幅（5.4:1）位图档位

| 横幅宽（1080p） | 1080p@1x | 1080p@2x | 4K@1x | 4K@2x |
| --- | --- | --- | --- | --- |
| 640 | 736 → 800 | 1472 → 1600 | 1472 → 1600 | 2944 → 3840 |
| 816 | 938 → 960 | 1877 → 1920 | 1877 → 1920 | 3754 → 3840 |
| 860 | 989 → 1280 | 1978 → 2560 | 1978 → 2560 | 3956 → 4096 |
| 1160 | 1334 → 1600 | 2668 → 3840 | 2668 → 3840 | 5336 → ✕ |
| 1680 | 1932 → 2560 | 3864 → 4096 | 3864 → 4096 | 7728 → ✕ |
| 1760 | 2024 → 2560 | 4048 → 4096 | 4048 → 4096 | 8096 → ✕ |

规则：

- 宽度 ≥ 1160 的横幅**不要求 4K@2x**：所需位图超过 4096，实际收益接近 0。4K 屏按 4096 交付，允许轻微上采样（≤ 1.3 倍）。
- 高度按比例带出：`源高 = 源宽 / 5.4`（可多留 5–10% 供裁切，但不得少于）。
- 最小源图尺寸（1080p @1x）：半幅 1280×238；通栏 1920×356。推荐：半幅 1920×356，通栏 2560×474。4K 通栏：4096×759。
- 低于 1280 宽的横幅图在 55 寸以上屏幕会明显发虚；素材侧不要用 16:9 图 + contain 充数（两侧填充后有效像素更低）。

### 5.4 最小分辨率与规则

| 资源 | 最小 | 推荐 | 说明 |
| --- | --- | --- | --- |
| 2:3 海报 | 宽 ≥ 240 | 480–640 | 不低于卡片宽 × 1.15 后向上取档（160 宽卡 → 240） |
| 16:9 缩略图 | 宽 ≥ 480 | 640–960 | 视频截图优先原生 |
| 1:1 头像 | 宽 ≥ 160 | 240–320 | 圆形裁切 |
| 5.4:1 横幅 | 宽 ≥ 1280 | 1920–2560（通栏）；4K 4096 | 源图比例 ≥ 2:1，见 §4.6.5 |
| 2:1 主视觉 | 宽 ≥ 1280 | 1920–2560 | 需保留中部 50% 供文字 |
| 主视觉/背景 | 宽 ≥ 1920 | 2560–3840 | 允许 1.2 倍裁切 |
| 图标 | SVG | SVG | 不提供位图 |

其他：优先 AVIF/WebP；禁止把 1080p 图放大到 4K；同一卡片在不同 DPR 下只换 `srcset`，不改布局。

## 6. 间距体系

### 6.1 基础单位

`base = 4`（1080p 设计像素）。阶梯：

```
4, 8, 12, 16, 24, 32, 48, 64, 96
```

大于 96 用「列宽/卡片宽的倍数」，不再新增间距 token；小于 4 只允许 1px 发丝线与 2px 进度条。

### 6.2 五级间距

| 层级 | 取值 | 用在哪 | 依据 |
| --- | --- | --- | --- |
| L1 元素内 | 4–8 | 图标与文字、标签与数值、进度条与底边 | 视觉分组 [惯例] |
| L2 元素间 | 8–16 | 按钮组、列表项内部、卡内文字行 | 8px 栅格 [推导] |
| L3 区块内 | 16–24 | 卡片内容 padding、面板内边距 | 与卡宽 6–10% [惯例] |
| L4 区块间 | 32–64 | 货架之间、区块标题到内容 | 行高 1.5–2 倍 [惯例] |
| L5 页面边距 | 48–160（常用 ≤120） | 四边 `M` | §2 |

### 6.3 组合规则

- 同一页面最多出现 6 个不同间距值；超出说明层级混乱。
- 卡间距 `G` 与行间距 `R` 分开定义：海报墙 `R = 32–48`，货架 `R = 48–64`（含标题区）。
- 标题到内容的距离 ≥ 16，且 ≤ 内容的卡间距，避免「标题像上一区的内容」。

## 7. 字体

### 7.1 最小字号推导（3 m / 1080p）

视角与像素：

```
1° ≈ 52.4 mm @ 3 m
55" 16:9 屏宽 ≈ 1218 mm → 像素间距 ≈ 0.634 mm
目标 x-height ≈ 10 arcmin = 8.7 mm
em ≈ 17.4 mm → 27.4 px
65" 屏宽 ≈ 1440 mm → 0.75 mm/px → 23.2 px
```

结论：**正文下限 24px @1080p / 3m（55–65 寸）**；低于 20px 只允许非关键信息（版权、版本号）。[推导]

距离换算（同尺寸屏幕）：`minPx ≈ 0.09 × 距离(cm)`。4 m → 36px；3 m → 27px（55 寸）；2.5 m → 22px。屏幕更大时按像素间距同比下调（65 寸 / 3 m 可用 24px）。

### 7.2 字号阶梯

| Token | 字号 | 字重 | 行高 | 字距 | 用途 |
| --- | --- | --- | --- | --- | --- |
| Display XL | 96–128 | 200–300 | 1.0–1.1 | −0.02em（仅拉丁） | 首页时钟、超大标题 |
| Display | 64–80 | 300 | 1.05–1.15 | −0.01em | 主视觉片名 |
| Title 1 | 48–56 | 500–600 | 1.1–1.2 | 0 | 页面标题、详情片名 |
| Title 2 | 36–44 | 600 | 1.15–1.25 | 0 | 分区标题、弹窗标题 |
| Title 3 | 28–32 | 600 | 1.2–1.3 | 0 | 货架标题 |
| Body L | 26–28 | 400 | 1.35–1.45 | 0 | 简介、说明 |
| Body | 24 | 400 | 1.4 | 0 | **正文基准** |
| Label | 20–22 | 500–600 | 1.3 | 0 | 卡名、按钮、导航 |
| Caption | 18–20 | 400–500 | 1.3 | 0 | 元信息、时长 |
| Micro | 14–16 | 400 | 1.25 | +0.02em（全大写时） | 角标；**仅非关键** |

### 7.3 字重使用

| 字重 | 用在哪 | 限制 |
| --- | --- | --- |
| 200–300 | 仅 Display/时钟 | 低于 48px 禁止使用 |
| 400 | 正文、简介 | 大段文字 |
| 500 | 标签、导航、卡名 | 与 400 混用时只用在交互元素 |
| 600 | 标题、按钮 | 同屏不超过 2 处 |
| 700+ | 数字强调、角标 | 少见，避免「糊成一团」 |

### 7.4 行高与字距

- 行高：Display 1.0–1.15；Title 1.15–1.3；Body 1.35–1.45；Caption 1.25–1.35。
- 字距：CJK 0；拉丁大字号 `−0.01 ～ −0.02em`；全大写小字 `+0.02em`。
- 行长：单行 ≤ 28–32 个汉字（约 680–760px @24px）；超过改用两行或缩窄容器。
- 缩放后字号必须取整（§1.4）；不要出现 `23.7px`。

## 8. 图标

### 8.1 视框阶梯

| 视框 | 用途 | 最小线宽 | 线宽比 |
| --- | --- | --- | --- |
| 16 | 角标、内联 | 1.5 | 9.4% |
| 20 | 列表内、次要按钮 | 1.75 | 8.75% |
| **24** | **默认**（导航、按钮、卡片） | 2 | 8.3% |
| 32 | 导航栏、播放控制 | 2.5 | 7.8% |
| 40 | 磁贴/大按钮 | 3 | 7.5% |
| 48 | 首页主入口 | 3.5 | 7.3% |

规则：线宽在视框的 **7%–10%** 区间内，按 6 档插值（16→1.5、48→3.5，斜率 0.0625）：

```
stroke = clamp(1.5, 0.0625 × viewBox + 0.5, 4)
```

这 6 个值恰好落在表内，大于 48 的视框继续按上式外推并 clamp 到 4。低于 7% 在 3 m 外消失，高于 10% 图标变「实心块」。[惯例]

### 8.2 图标与文字

| 关系 | 值 |
| --- | --- |
| 图标-文字间距 | 0.35–0.5 × 图标尺寸（24 → 8–12） |
| 垂直对齐 | 图标视觉中心对齐文字 x-height 中心，不是行盒中心 |
| 图标与文字同色 | 是；图标不单独提高白度 |
| 纯图标按钮 | 目标 ≥ 48×48（1080p），图标本身 24–32 |
| 图标基线 | 不贴文字基线，下移 `(字号 − 图标高)/2 + 1` |

### 8.3 绘制规范

- 统一 24 视框、圆头圆角、2px 线宽；不同尺寸复用一个 SVG，不重画。
- 填充型图标与描边型图标不混用（同一层级只允许一种）。
- 状态图标（成功/失败）必须配文字，不能只靠颜色。

## 9. 焦点态（三种方案）

电视端没有鼠标，焦点是唯一的「当前位置」提示。**没有焦点态 = 不可用**。

### 9.1 方案 A：描边式（Border）

| 参数 | 区间 | 推荐 |
| --- | --- | --- |
| 描边宽度 | 2–4 | 3 |
| 描边颜色 | 白 85–100% | 白 92% |
| 外间隙 | 0–8 | 0（描边贴边） |
| 几何变化 | 无 | 无 |
| 附加 | 填充提亮 5–10% | +8% |

适用：密集网格、列表行、设置项、不能改变尺寸的布局。优点是不引起重排；缺点是远处不够醒目。

### 9.2 方案 B：环式（Ring）

| 参数 | 区间 | 推荐 |
| --- | --- | --- |
| 环宽 | 3–6 | 4 |
| 环与卡片间隙 | 8–12 | 10 |
| 环颜色 | 白 90–100% + 外圈黑 30%（对比底） | 同 |
| 几何变化 | 无 | 无 |

实现：以环宽 4、间隙 10 为例，`::after { inset: -14px; border: 4px; }`（外缘 −14、内缘 −10）。环宽取 6 时改为 `inset: -16px`。适用：浅色/复杂背景、需要强提示的主入口。缺点是占空间，网格间距 < 24 时环会互相碰到。

### 9.3 方案 C：放大式（Scale）

| 参数 | 区间 | 推荐 |
| --- | --- | --- |
| 放大倍数 | 1.04–1.12 | 1.06–1.08 |
| 阴影 | y 12–32 / blur 32–64 / spread −2 ～ −8 | 0 18 40 −4 |
| 阴影透明度 | 35–50% | 45% |
| 动效 | 120–200ms ease-out | 160ms |

适用：首页主入口、货架卡片、主视觉。**禁止 > 1.15**：会产生卡片互相覆盖、文字重排、滚动抖动。

宽幅横幅的限制：`transform: scale()` 不参与布局，**不会把上下内容挤开**，只会覆盖相邻区块。通栏横幅放大 1.06 时宽度会超出内容区（1760 × 1.06 = 1866 > 1760），直接压到安全边距外，因此**通栏禁止放大**；半幅横幅最多 1.03–1.04，且上下需预留 `h × (scale − 1) / 2 + 阴影模糊 / 2`（约 8–12）的间隙。需要「呼吸感」时改为内部图片放大（容器 `overflow: hidden`，图片 scale 1.02–1.04），外部尺寸不变。

### 9.4 组合建议

| 场景 | 推荐组合 |
| --- | --- |
| 首页六宫格/主入口 | C + A（放大 1.06 + 3px 描边） |
| 海报墙 | A 或 C（1.04–1.06），不要环 |
| 横向货架 | C（1.06）+ 轻微提亮 |
| 列表行/设置 | A（整行提亮 + 左侧 4px 竖条） |
| 按钮 | A（描边）+ 填充提亮 |
| 通栏横幅（5.4:1） | A 描边 3–4px + 填充提亮 8%（可加左侧 6–8px 强调条）；**禁止 C** |
| 半幅横幅 | C 放大 1.03（≤ 1.04）+ 轻阴影；预留 8–12 间隙，或改内部图片微放大 |
| 2:1 主视觉 | A 描边（首选）；独立 hero 页可用 C 1.02–1.03 |
| 不可用项 | 不显示焦点环，白度降到 30–40%，仍可聚焦但不触发 |

统一规则：**同一页面只允许一种焦点语言**（要么都放大，要么都描边），混用会让人误判层级。

## 10. 色彩

### 10.1 明度阶梯（HSL 的 L 或感知亮度）

| 层级 | 明度 | 示例 | 用途 |
| --- | --- | --- | --- |
| 底（Base） | 3–8% | `#05080A` / `#0A0D10` | 全屏背景 |
| 面板（Panel） | 8–14% | `#14181C` | 设置面板、侧栏 |
| 浮层（Overlay） | 14–22% | `#1A1C21` | 弹窗、抽屉 |
| 控件（Control） | 18–26% | `#22282E` | 按钮、输入框 |
| 分隔线 | 24–32% 白 10–16% | `rgba(255,255,255,.12)` | 1px 线 |

层级之间至少相差 **6 个百分点明度**，否则 3 m 外看不出层次。[经验]

### 10.2 文字对比度

| 文本 | 对比度 | 说明 |
| --- | --- | --- |
| 正文 | ≥ 4.5:1（WCAG AA） | TV 建议 ≥ 7:1 |
| 大字号（≥24px/600） | ≥ 3:1 | WCAG AA Large |
| 次要信息 | ≥ 3:1 | 不得低于 2.5:1 |
| 禁用 | 不要求 | 但需与可用态可区分 |

文字白度阶梯：100 / 90 / 75 / 60 / 45 / 30%（最后两档只用于非关键）。**不要用纯白铺大段文字**（HDR 下会溢光），正文用 92–96%。

### 10.3 强调色

- 全屏强调色面积 ≤ **10%**；单屏只允许 1 个强调色相。
- 强调色只用于：焦点、进度、选中、关键 CTA。不要用于大面积背景。
- 语义色：成功/失败/警告各 1 个，饱和度 60–80%，且必须配图标或文字。
- 图片上的文字必须有 scrim（黑 0→55%→92%）或实色底板。

## 11. 动效

| 类型 | 时长 | 缓动 | 说明 |
| --- | --- | --- | --- |
| 焦点移动/放大 | 120–200ms（推荐 160） | `cubic-bezier(.2,.8,.2,1)` 或 `(.16,.84,.24,1)` | 只动 `transform`/`opacity`；不要回弹 |
| 按下反馈 | 80–120ms | `ease-out` | 缩放 0.97–0.99 或亮度 −8% |
| 面板展开（抽屉/浮层） | 200–320ms（推荐 240），退出 160–220 | `cubic-bezier(.2,.8,.2,1)` | 位移 + 透明度；背景 scrim 同步 200ms |
| 页面切换 | 240–400ms（推荐 300） | `cubic-bezier(.4,0,.2,1)` | 淡入 + 8–24px 位移；不要全屏缩放 |
| 骨架/加载 | 900–1400ms 循环 | `ease-in-out` | 只动透明度或渐变位置 |
| 提示 Toast | 入 160 / 停留 2400–3200 / 出 200 | `ease-out` | 不抢焦点 |

规则：

- 遥控器连续按键时，焦点动画必须可被下一次按键打断（不要排队）。
- 距离越远时长可略增，但不超过上表上限。
- 支持「减少动态」：关闭位移与缩放，只保留 80ms 透明度。
- 60fps 预算：单帧 ≤ 16.6ms；禁止动画 `width/height/top/left/filter`。

## 12. 三种布局与切换

### 12.1 海报墙（Grid）

| 项 | 规则 |
| --- | --- |
| 列宽 | §3 表格 |
| 横向间距 | `G`（24–48） |
| 行间距 | 32–48（不含卡内文字） |
| 行 pitch | `卡高 + 行间距 + 文字区高` |
| 每屏行数 | 2–3 行（1080p） |
| 滚动 | 整行滚动，焦点到边缘才滚；滚动步长 = 行 pitch |
| 对齐 | 所有行共享左右边距与列宽；不许「最后一行居中」 |

### 12.2 横向货架（Shelf/Rail）

| 项 | 规则 |
| --- | --- |
| 卡宽 | 与海报墙同列宽（切换不跳变） |
| 露边 | 右侧露出下一张的 8–12%（提示可横移） |
| 间距 | 16–32（比网格紧） |
| 标题 | 距货架顶 0；标题与卡间距 12–16 |
| 货架间距 | 48–64 |
| 焦点 | 放大式，放大后不得遮住标题或下一行 |

### 12.3 列表行（List）

| 项 | 规则 |
| --- | --- |
| 行高 | 单行 56–64；双行 72–88；三行 96–112 |
| 缩略图 | 单行 40–48 方形；双行 64–80 方形/16:9 |
| 内边距 | 左右 16–24；图-文 12–16 |
| 行间距 | 0（用分隔线 1px）或 8 |
| 焦点 | 整行提亮 + 左侧 4px 竖条；不改行高 |
| 文本 | 主 20–22/500；次 18/400，白 60% |

### 12.4 混排对齐原则

1. **共享左基线**：海报墙、货架、列表的左边距必须是同一个 `M`。
2. **共享列宽**：同一页面里货架卡宽 = 网格列宽；切布局不改变卡宽。
3. **共享标题栅格**：区块标题与卡片左缘对齐；标题不缩进。
4. **共享行节奏**：`区块间距` 一致（48–64），不要一处 32 一处 80。
5. **焦点不越界**：放大后的卡片不得进入相邻区块的标题区。
6. **滚动容器**：整个内容区一个滚动上下文；不要嵌套两层纵向滚动。

## 13. 常见错误与修法

| # | 症状 | 原因 | 修法 |
| --- | --- | --- | --- |
| 1 | 最后一列悬空/被裁 | 边距与列宽不匹配，或用了绝对定位 | 用 §3.2 公式反解 `G`；布局用 flex/grid，不用手写 x |
| 2 | 4K 上字号出现 `31.99px` | 对字号做等比缩放 | 字号按档位表取整；或用 `round()`；不要链式缩放 |
| 3 | 文字被电视裁掉 | 把视觉边距当安全区 | 文字进标题安全区（90%），焦点环进动作安全区（93%） |
| 4 | 边缘发丝线消失 | 0.67px 线宽 | 用 `max(1px, 1×s)` 或物理 1px |
| 5 | 焦点环被裁 | 父容器 `overflow: hidden` | 给环留 `inset` 空间，或改用内描边 |
| 6 | 放大后卡片互相遮挡 | 焦点倍数 > 1.12，或间距 < 24 | 倍数 ≤ 1.08，`G` ≥ 24，或改描边式 |
| 7 | 货架与网格切换时卡片跳动 | 两处卡宽不同 | 统一列宽；货架复用网格 `cw` |
| 8 | 海报上文字看不清 | 亮图无 scrim | 加底部渐变 0→55%→92%，或文字底板 |
| 9 | 图标糊/粗细不一 | 位图图标、多个线宽 | 统一 SVG 24 视框，线宽 7–10% |
| 10 | 正文太长读不动 | 单行 > 32 汉字 | 限制容器宽 680–760px，或拆行 |
| 11 | 滚动卡顿 | 动画 width/height/filter | 只动 `transform/opacity`；图片预解码 |
| 12 | 设置页两套边距 | 抽屉内又加了一层 padding | 只保留一套 `M`，抽屉用内边距而非外边距 |
| 13 | 焦点丢失 | 页面切换后未指定初始焦点 | 每次进入页面显式设置焦点；返回时还原 |
| 14 | 颜色层次不清 | 面板与底只差 2–3% 明度 | 层间 ≥ 6 个百分点；或加 1px 分隔线 |
| 15 | 强调色铺满屏 | 把品牌色当背景 | 强调色 ≤ 10% 面积，只做焦点/进度/CTA |
| 16 | 竖屏/方图塞进 2:3 槽 | 资源比例不匹配 | 按容器比例出图；禁止拉伸，用 `object-fit: cover` + 焦点裁切 |
| 17 | 横幅高度只有 40–80，文字放不下 | 把 5.4:1 当普通卡按单列取宽 | 按跨列/通栏取宽（§4.6.2）；`h < 120` 直接改 16:9 |
| 18 | 通栏横幅聚焦后越出边距、压住上方标题 | 对通栏用了 `scale()` | 通栏改描边；半幅放大 ≤ 1.04 并预留 8–12 间隙 |
| 19 | 16:9 剧照裁进 5.4:1 后人物被切头 | 纵向裁掉 67%，超出安全阈值 | 只裁 ≤ 60%；否则用专用横幅图或 `contain` + 模糊填充 |
| 20 | 横幅圆角像直角 | 沿用 `0.055w` 后被 28 截断 | 横幅按短边算 `r = clamp(8, 0.10h, 36)`（§4.4） |

| 场景 | 处理 | 依据 |

| 21:9 超宽（2560×1080） | `s=1`；内容区仍按 1760 设计，居中后左右各留 `(W − 1760)/2 = 400`；不增加列数、不拉宽卡片，只有背景与氛围层可铺满 | [推导] |

## 16. 可访问性与遥控器

### 16.1 硬性检查项

| 项 | 要求 |
| --- | --- |
| 正文对比度 | ≥ 4.5:1（推荐 7:1）；大字 ≥ 3:1 |
| 焦点可见性 | 焦点环与相邻背景 ≥ 3:1；任何页面不得出现无焦点态 |
| 最小目标 | 48×48；相邻可聚焦元素间距 ≥ 8 |
| 最小字号 | 20（角标 14–16 仅限非关键信息） |
| 颜色之外 | 状态必须同时有图标或文字，不只靠颜色 |
| 动效偏好 | 支持「减少动态」：关位移/缩放，保留 80ms 透明度 |

### 16.2 遥控器路径

- 每个页面进入时必须显式设置初始焦点；返回时还原上次焦点。
- 任意内容 ≤ 4 次方向键可达；抽屉/浮层层级 ≤ 3。
- 连续按键时焦点动画可被打断，不排队。
- 焦点不得落到不可见、禁用但仍可聚焦、或被遮罩盖住的元素上。
- 长列表焦点到边缘才滚动，步长 = 行 pitch；不做焦点跟随的惯性滚动。
- 返回键优先级：关浮层 → 关抽屉 → 返回上一页；不得直接退出应用。

### 16.3 对比度的计算前提

对比度必须在**最终合成背景**上计算：图片 + scrim、半透明面板叠加后的实际颜色，而不是设计稿的色值。半透明面板上的文字要按最坏情况（最亮帧）验算。

## 17. 规则的执行边界

| 规则 | 能否直接执行 | 说明 |
| --- | --- | --- |
| 网格、卡片、圆角、间距、字号档 | 是 | 纯算术，可按 §1.4 取整 |
| 位图档位 | 是，但依赖 DPR | 盒子可能谎报 DPR：用 `物理分辨率 / CSS 视口宽` 反推有效 DPR，再套公式 |
| 模糊半径上限 | 否 | 96 是经验上限，需在目标盒子实测帧率 |
| 对比度 | 需实测合成色 | 见 §16.3；设计稿通过不代表叠加后通过 |
| 「3 m 外可见」类结论 | 否 | 属推导/经验，需现场验证，不应写成验收硬指标 |
| 焦点语言唯一 | 否 | 属于设计评审约束，代码无法自检 |
| HDR 表现 | 否 | 取决于平台图形层与显示器映射，Web 层只能控制颜色值 |
| 「减少动态」 | 是 | 读取系统偏好或提供应用内开关 |

```
C        = W0 − 2M
cw       = (C − (N−1)G) / N
G        = (C − N×cw) / (N−1)

h(5.4:1) = cw / 5.4                // 且 h ≥ 120，否则改比例

span(k)  = k × cw + (k−1) × G      // 横幅跨列宽
r        = clamp(6, 0.055×cw, 28)
r(banner)= clamp(8, 0.10×h, 36)    // 宽幅按短边
keep     = (1/5.4) / (h_src/w_src) // 裁进 5.4:1 的保留带
imgW     = ceil(cw × s × DPR × 1.15)
minFont  ≈ 0.09 × 距离(cm)          // 1080p、55–65 寸
stroke   = clamp(1.5, 0.0625 × viewBox + 0.5, 4)
ring     = max(3, round(4×s))       // 1080p ≥3，4K ≥6
```
